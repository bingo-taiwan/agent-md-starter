# 收工：寫交接檔

交接檔是跨 session 的記憶橋樑。讀者是「下一個沒有這次對話 context 的 agent」，它只能讀檔案。
每個專案一份 `docs/handoff.md`，**每次收工整份覆寫**，它代表專案「現在的快照」，不是日記。
歷史版本靠 `git log -- docs/handoff.md` 回看。

## Step 1：回顧這次做了什麼

```bash
git log --oneline -10
git status -sb
git stash list
```

同時回想對話裡的關鍵決策、踩過的坑、沒做完的事。

## Step 2：每個動過的 repo 都要 push（強制）

commit 不等於 push。只 commit 沒 push 的工作，物理上只存在這台機器，換一台就會被回退。

1. 未 commit 的改動 / stash → 先 commit（沒做完就 commit 成 WIP）
2. `git push origin <branch>` ← 少了這步前面全白做
3. 確認 `git rev-parse HEAD` 等於 `origin/<branch>`
4. 刻意不 push 的（例如衝突要留給人解）→ 在交接檔待辦明寫「⚠️ 未 push，原因…」

## Step 3：覆寫 `docs/handoff.md`

用 `docs/handoff.md` 裡的模板（frontmatter + 五段）。這次沒實質進展（只是聊天、查資料）→ 跳過，告訴用戶「沒有需要交接的內容」。

一次 session 動了多個專案 → 各自的 repo 各寫一份。

## Step 4：狀態標記（結構性防呆，強制）

交接檔裡每一個「完成」都必須帶標記，**裸 `✓` / `✅` / 「已修」一律無效**，視同未驗證：

| 標記 | 意義 | 下一棒怎麼對待 |
|------|------|--------------|
| `[實證✓]` | 本次親自驗到「使用者實際看到那層」（畫面 / DB 真值 / 指令輸出），**當行附證據** | 可信，仍可抽驗 |
| `[宣稱✓·未複驗]` | 前一棒、廠商、舊紀錄說做了，這次沒重驗 | **一律當未驗證**，自己重驗到 `[實證✓]` 才能說完成 |
| `[待辦]` | 還沒做 | 接續做 |
| `[定調·非bug]` `[跳過]` `[排期]` | 判定不需處理或另排時間 | 讀原因，別重複查 |

寫不出證據的 `[實證✓]` 要降級成 `[宣稱✓·未複驗]`。
開工時讀到上一棒的 `[宣稱✓·未複驗]`，在你親自重驗之前，不准對用戶說它完成。

## Step 5：值得永久留的東西不要只放交接檔

| 這次學到的 | 放哪 |
|-----------|------|
| 跨專案都有用的教訓（工具行為、環境陷阱） | agent 的記憶目錄，或 AGENTS.md 的環境段 |
| 這個專案的架構決策 | 專案 README / 設計文件 |
| 近期進度、下一步 | 交接檔（Step 3 已做） |

## Step 6：收尾

告訴用戶：交接檔更新到哪、哪些 repo 已 push、有沒有刻意留下沒 push 的東西。然後可以關 session 了。

## 品質標準

- 整份 < 30 行，超過就砍
- 寫結論帶原因，不寫逐步操作、不寫 debug 過程
- 拿掉某行後下個 session 也不會卡住 → 那行不用寫
